## 起動
Flutter stable SDKをインストールし、`flutter`をPATHに追加してください。検証環境はFlutter 3.47.9 / Dart 3.13.7です。同じバージョンでの再現を推奨します。SDKは成果物に含めていません。

初期設定の対象OSはAndroid API 24以上、iOS 15.0以上です。

Windowsでは、ZIPを `C:\dev\phrase_flow` など英数字だけのパスへ展開してから開発コマンドを実行することを推奨します。今回のSDKでは、日本語を含むパスで解析ツールが終了する現象があり、同一ソースを英数字のパスへコピーして検証しました。

```sh
cd phrase_flow
flutter --version
flutter doctor -v
flutter pub get
flutter devices
flutter run -d <device-id>
```

AndroidはAndroid Studio、Android SDK、エミュレーターまたはUSBデバッグ有効な実機が必要です。必要に応じて `flutter doctor --android-licenses` を実行します。iPhone / iOS SimulatorはMac、Xcode、FlutterのiOS開発環境が必要です。

ブラウザーで同じFlutter実装を確認する場合：

```sh
flutter run -d chrome
```

Webは確認用の追加ターゲットです。ブラウザーの保存領域はAndroid / iPhoneの保存領域とは別です。プライベートモードやサイトデータ削除で記録を失う場合があります。

## Androidビルド

```sh
flutter build apk --debug
flutter build appbundle --release
```

APKは `build/app/outputs/flutter-apk/app-debug.apk`、AABは `build/app/outputs/bundle/release/app-release.aab`。リリースビルドはアップロード鍵を `android/key.properties` に設定してから実行します（`android/key.properties.example` 参照）。秘密鍵・パスワードをバージョン管理に含めないでください。未設定時はリリースビルドを明示的に停止する設定です。

暫定applicationIdは `com.example.phrase_flow`。公開前に自分が管理する一意のIDに変更し、Kotlinのパッケージとディレクトリ、iOSのBundle Identifierを合わせて更新してください。

## 問題の追加
英文ごとの解説は、`answers` の各要素を `{"text":"英文", "explanation":"ニュアンス・使い方"}` として記載します。解説は省略でき、従来の文字列だけの要素も読めます。問題全体の文法メモは `note` に記載してください。具体例は詳細仕様にあります。

`assets/questions.json` のquestionsに新しい固定IDの問題を追加します。既存IDは変更・再利用しません。contentVersionを更新し、`pubspec.yaml` のバージョンと `+` 以降のビルド番号を上げ、自動テスト後に新バージョンを配布します。既存記録は問題IDで引き継ぎます。分類を追加する場合は `lib/domain.dart` も変更します。

英文を追加・変更した場合は、以下の音声再生成も必要です。対応する音声がない場合は自動合成せず、再生エラーを表示します。問題文だけ変更して古い音声を誤って流すことを防ぐため、全文一致で音声を対応付けます。

## 同梱音声の再生成（開発時のみ）
Node.js 24で検証。プロジェクト直下から実行します。

```sh
cd tools
npm ci
node generate_audio.mjs ..
cd ..
flutter test
```

初回は公開モデル（約326MB）と音声データをダウンロードします。PCで推論し、英文を音声生成サービスへ送信しません。モデルは `tools/.cache`、音声は `assets/audio` に保存します。モデルとnode_modulesをアプリや配布ZIPへ含めないでください。既存の音声はファイルハッシュを確認して再利用し、必要な英文だけ生成します。声やモデル・生成方式を変える場合は、全音声の再生成と校聴が必要です。

`assets/audio/manifest.json` に英文、英文ハッシュ、音声パス、ファイルハッシュ、長さ、モデル・声・モデルのハッシュを保存します。テストで3,467例文すべてとの対応とファイルの整合性を確認します。主観的な自然さ・発音の正しさは、公開前に英語話者の校聴で確認してください。
